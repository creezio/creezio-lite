# Generated documents and native commit access

`createGeneratedFilePublicationPort()` (exported by `runtime/core/index.ts`) stages generated bytes in R2 with durable D1 intents. Apply additive migration `0013_generated_files.sql` first. No worker credentials or invented principal are accepted: methods take the real `AppOperationContext` with its live native access lease, authorized operation and manifest capabilities.

The port implements `stage(ctx, {id, ownerId, generation, digest, name, contentType, bytes, requiredCapabilities})`, `publicationProof(ctx, staged)` and `abandon(ctx, staged)`. SHA-256 is checked against the bytes (10 MiB maximum). The immutable identity is workspace + intent + generation; conflicting content or metadata is refused. Staging/retry uses its deterministic private object key. Before publication there is no `lite_files` row, so native lists, metadata and downloads cannot disclose pending bytes.

**The application must include every statement returned by `publicationProof` in the same D1 batch as its current resource predicates, job generation/fence/version CAS, final file pointers and audit.** The native proof checks the exact durable intent, non-abandoned state, native authorization epoch and absence of a deleted/competing published file. A failure anywhere rolls back all metadata, publication state and business effects. Only one generation per intent may publish. The application owns job generation order; the native generation identifier is opaque. Executing the proof alone does not validate the business job.

Every download still uses the application's current native `ScopeProvider.fileFilter`. The application must relate a generated file to its ready job and current resource/capability predicates; persisted manifest data never grants read access. The native endpoint rechecks the access epoch, membership, credential, receipt expiry, tombstone and file scope together after awaiting R2. A revoked or newly invisible file returns no bytes.

Failed uploads retain a durable staging intent for an explicit authorized retry. `abandon` permanently prevents publication of that generation before deleting its object, returns `cleanup_pending` on storage failure, and is retryable. It never deletes a published object. There is no automatic background sweep: jobs must retry the intent or cleanup explicitly. A crash after writing bytes remains discoverable by workspace/intent/generation on retry.

For other business writes, include `requestAccessCommitGuard(ctx.access)` as a SQL statement in the same D1 transaction as **all** effects and audit. It returns `{sql, bindings}` and aborts the whole batch when the server-owned epoch, role, membership, receipt lifetime or machine credential has changed. It does not authorize an operation by itself. `commitRequestAccessBatch(db, access, preparedStatements)` is the prepared-statement wrapper; native CRUD/upload/delete use it automatically when access profiles are enabled. Existing applications without profiles preserve legacy behavior. Extensions issuing their own D1 batches must explicitly include this native guard.

Local proof: `tests/generated-files-native.test.mjs` runs against actual Miniflare D1/R2. It covers durable retry, hidden staging, digest/tenant conflicts, transaction rollback, replay, competing generations, cleanup failure, HTTP PATCH suspended before revocation and download revocation while R2 is awaited.

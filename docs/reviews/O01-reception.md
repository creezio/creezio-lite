## Limites

- Aucun appel réel à l’API Cursor depuis ce run (aucune `CURSOR_API_KEY` dans son environnement) : tous les appels des tests sont des `fetch` simulés. Les identifiants et combinaisons de `cursor-model.json` proviennent du relevé du catalogue authentifié du compte (`2026-09-16T18:25:18Z`) transmis et confirmé par le pilote connecté ; le préflight réel `preflight --select fable|opus|grok` est effectué par le pilote connecté. Un écart éventuel se corrige dans `cursor-model.json` par PR, jamais automatiquement.
- L’API publique n’expose pas le modèle d’un run : `modelObserved` reste `null` dans les reçus du script. La sélection acceptée à la création et la requête de reprise acceptée sont distinctes ; aucune n’est une preuve de la sélection effective. Le nom déclaré par l’agent (`run-info`) n’encode pas le contexte et ne prouve pas l’absence de repli fournisseur. Un routage interne du fournisseur, distinct de notre sélection, reste possible ; le standard ne le promet ni ne le contourne.
- Reprise : l’API ne renvoie pas l’identifiant de la requête de suite ; la réconciliation repose sur `latestRunId` de l’agent comparé au run d’avant tentative. Si un autre acteur lance un run sur le même agent entre la tentative et `reconcile`, ce run serait attribué à la suite ; le registre privé et l’agent par mission limitent ce cas, non couvert techniquement.
- `status --follow` termine par une sortie indisponible explicite (code 3) sur erreur réseau/5xx/quota ; l’orchestrateur relance la même commande, le fichier d’état conserve le dernier relevé. Aucun mécanisme de veille supplémentaire.
- Le script n’importe pas le transport métier `runtime/core/agent-providers` : la copie installée doit fonctionner sans le kit et sans TypeScript ; le provider métier D03 est inchangé.
- Aucune adoption réelle d’une application de production n’a été effectuée ; la fixture est une application générée par le kit. Les pilotes appliquent `lite adopt` depuis la version validée et ajoutent eux-mêmes la mention du standard à leur `AGENTS.md`.
- Le registre privé et les fichiers d’état sont fournis par l’orchestrateur hors dépôt ; le script ne l’impose pas techniquement.
